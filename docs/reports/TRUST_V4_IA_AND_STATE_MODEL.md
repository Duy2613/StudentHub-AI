# Trust V4.2 IA and state model

T1 design: editorial reading surface, a compact input form and contextual aside; one conclusion-first result, claim selection, evidence and source lists, comparison, then canonical handoffs. Shared `--canvas`, `--surface-*`, `--text-*`, border/status tokens; light and midnight; no new motion runtime.

Seven evidence groups: entry; claims/processing; standard result; evidence/sources/comparison; difficult outcomes; integration/revision; mobile 390. Actual browser captures follow implementation, before any optional motion. No motion is planned for this scope.

Execution (`idle/pending/processing/complete/failed`) is independent of assessment (canonical truth), freshness (submitted draft snapshot and observed revision), availability and authorization. Request generation + AbortController protect response ownership. Auth principal keys remount all private state. Final response identity must agree with accepted streamed binding; terminal data gets no bypass. Missing metrics stay null.

Changing draft preserves the prior result but labels it as belonging to the submitted input. A failed new request keeps the previous result labeled as previous. No autosubmit, auto retry, server cancel claim, raw-text URL handoff or persistent private draft.

Performance targets selected for this task: local production useful input/result median < 2s, evidence/claim interaction median < 250ms, initial encoded JS < 600KiB, no optional graph/WebGL in core. Five samples, medians/ranges, proxy timing explicitly labeled. These are LAB project targets, not field CWV or provider latency promises.
