## Classification rules

- **EXISTS** means a durable or server-owned contract is present for the capability as requested.
- **PARTIAL** means a related implementation exists but does not meet the V5 semantics or its runtime is unverified.
- **MISSING** means no matching implementation was found after inspecting `frontend/src`, `frontend/tests`, and `database/migrations`.
- **UNKNOWN** means repository evidence cannot establish whether the capability exists outside this checkout.

`quiz_v2`, `expert_score_v2`, and `room_v2` were not found. The app already has a qualification quiz, a reputation ledger, Trust URL/file handling, and durable SSE. The feature names above are not proposed entities.

## Reuse decisions

1. Extend the canonical Expert area; do not replace the existing directory, profile, request, queue, case, evidence or assessment surfaces.
2. Keep qualification quiz (`expert-qualification.v1`) distinct from daily source-based missions; do not repurpose its inline policy questions as factual source questions.
3. Use the existing `private.reputation_events` ledger and existing Expert reputation projection as the only reputation foundation. Additive V5 event linkage/policy must not redefine existing credentials, assessment quality, or current public stars.
4. Reuse `POST /api/v1/trust` / `TrustOrchestrator` for supported inputs; room integration must bind the returned durable case/revision and report blocked/unavailable honestly.
5. Reuse the existing durable realtime provider only after adding room-authorized membership checks; generic subject-scoped Expert SSE is insufficient for room confidentiality.
6. Preserve all dirty files and unrelated work. V5 implementation should be additive, migration-backed, behind server-owned feature enablement, and isolated from production/Main.

## Audit conclusion

`EXPERT_V5_BASELINE = PARTIAL`. Several adjacent platform primitives exist, but the requested complete product flow is not present. In particular, no qualifying real-source quiz bank, mission lifecycle, verification room, room-specific authorization/presence, host/supervisor adjudication, or room reputation settlement was found. No runtime or staging assurance is claimed by this static audit.
