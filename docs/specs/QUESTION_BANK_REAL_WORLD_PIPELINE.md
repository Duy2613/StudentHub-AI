# Real-world Question Bank and Mission Pipeline

## Scope and source-of-truth rules

This change extends the existing Expert V5 source registry, immutable source snapshots, canonical Trust cases/claims/evidence, question versions, mission attempts, and progression. It does not add a parallel Trust graph or change the existing `SOURCE_QUIZ`, `LIVE_ROOM`, or `SUPERVISOR_REVIEW` mission contract. Text, URL, image, QR, and mixed scenarios bind to persisted Trust case IDs and canonical claim/evidence IDs. A URL may also bind to the existing Expert V5 source snapshot. Raw input bytes, answer keys, and rubric keys stay server-side.

The AI generator produces drafts only. Deterministic validation checks bounded structure, registered modality/type, resolvable source/claim/evidence IDs, answer shape, and duplicates. Editorial activation still requires an authenticated human reviewer and explicit review checks. An AI validation result never sets a question to `ACTIVE`.

## State transition matrix

| State | Trigger | Action / system response | User-visible result | Error and boundary handling |
| --- | --- | --- | --- | --- |
| `INPUT_IDLE` | Authenticated authorized editor opens intake | Accept one canonical TEXT, URL, IMAGE, QR, or declared mixed-input package | Intake form remains editable | Anonymous, oversized, malformed, or unsupported payload is rejected before Trust |
| `INPUT_VALIDATING` | Editor submits input with idempotency key | Validate modality, required URL registry, image artifact authorization/hash, QR format, UTF-8 bounds, and mixed-input count | Show validation progress | Unsafe/private URL, invalid artifact, missing idempotency key, or mismatched modality is rejected; do not fetch or persist a scenario |
| `TRUST_INGESTING` | Boundary checks pass | Invoke canonical Trust V5; require durable authenticated case persistence; reuse canonical `public.trust_cases`, `public.claims`, `public.claim_sources`, and `public.evidence`; reuse V5 URL snapshot where applicable | Show Trust ingestion state | Trust failure, persistence failure, zero evidence, or unresolved canonical references leaves no question-eligible scenario |
| `SCENARIO_READY` | Canonical case and evidence exist | Store scenario metadata and links to canonical cases, snapshots, claims, evidence, and authorized media references; compute stable package digest | Show evidence map and freshness | Duplicate idempotency key with different input is a conflict; private media ID is never returned in public DTOs |
| `GENERATION_RESERVED` | Authorized editor requests bounded generation | Create immutable run ID; clamp batch size/calls/retries/timeout; reserve no more calls than requested; build package only from canonical metadata, snapshots, claims, evidence, and authorized media | Show run ID and bounded progress | Disabled/missing Gemini route, exhausted budget, or invalid package stops before provider call |
| `AI_DRAFTED` | Gemini returns structured output | Persist provider/model/template/input digest/output digest and draft candidates; keep answer/rubric private | Draft count and run telemetry only | Invalid JSON, unknown IDs, unsupported facts, unsafe output, or provider failure is rejected with bounded code and no raw provider body |
| `GROUNDING_REJECTED` | Candidate cites missing or unrelated canonical IDs, lacks answer evidence, or has unsupported answer shape | Record rejection reason and continue only within the reserved call budget | Candidate marked rejected | Never coerce unknown references into local IDs or use Trust verdict as the quiz answer |
| `QUALITY_REJECTED` | Candidate is ambiguous, has repeated/degenerate options, duplicate normalized prompt, implausible choice set, or insufficient evidence | Record one or more deterministic rejection reasons | Candidate marked rejected | No attempt to manufacture scenario coverage by paraphrasing |
| `AUTO_VALIDATED_REVIEW_REQUIRED` | Structural grounding and quality checks pass | Persist immutable draft/version; apply exact/normalized and source+claim dedup; semantic comparison runs only when a configured embedding route is available | Draft is available to authorized editorial review | Auto-validation is not human approval; no client receives answer key or rubric |
| `ACTIVE` | Human reviewer submits all required review checks | Recheck freshness, current hashes, registered evidence/claims, answer references, difficulty and distractors; activate that exact question version | Active in quiz/mission selection | Missing review check or stale source leaves it draft/revalidation-required |
| `ASSIGNED` | Verified Expert scope receives a daily mission | Select canonical active/fresh question; bind attempt to exact question ID/version; expose only prompt, choices, and safe source projection | Quiz/mission can start | No eligible domain/question returns the existing no-validated-question state |
| `SUBMITTED` | User submits answer | Validate bounds, lock exact submitted answer, evaluate server-side, write idempotent answer/event/progression | Return score, explanation, resolved evidence, and source after submission | A second identical submit is idempotent; a different answer after submission is rejected |
| `REVALIDATION_REQUIRED` | Source hash changes, source becomes unavailable, or freshness window expires | Mark serving question unavailable; preserve past attempt version and result; require new review/version | Existing history remains readable; stale item is no longer assigned | Never rewrite historical attempts or silently keep an unsupported answer active |
| `FAILED` | Any database/provider/network boundary fails | Roll back current transaction, keep prior durable versions, record bounded run failure | Retry only under a new/valid idempotency key and reserved budget | Do not expose provider secrets, raw evidence payloads, answer key, or internal storage paths |

## Contract and acceptance invariants

- Supported modalities: `TEXT`, `URL`, `IMAGE`, `QR`, `TEXT_URL`, `TEXT_IMAGE`, `IMAGE_URL`, `QR_URL`, and `TEXT_URL_IMAGE`.
- Supported question types: the existing `SINGLE_CHOICE`, `MULTIPLE_CHOICE`, `TRUE_FALSE`, plus `MULTI_SELECT`, `BEST_EVIDENCE`, `SOURCE_RANKING`, `CLAIM_CLASSIFICATION`, `CLAIM_EXTRACTION`, `MISSING_CONTEXT`, `CONTRADICTION`, `TIMELINE`, `ENTITY_RESOLUTION`, `NUMERICAL_REASONING`, `SOURCE_AUTHORITY`, `IMAGE_CONTEXT`, `QR_SAFETY`, `URL_REDIRECT`, `EVIDENCE_MATCHING`, and `FINAL_VERDICT`.
- A candidate needs at least one durable Trust case, one canonical evidence row, resolved source links, a current package digest, and resolvable evidence/claim IDs. A URL question additionally needs its successful canonical source snapshot.
- Candidate generation is bounded by batch size, maximum calls, retry count, timeout, and output size. Each run has an ID and request/cost/latency outcome metadata; API keys and raw upstream bodies are excluded.
- Question versions are append-only by convention. Mission attempts reference `(question_id, question_version)` and retain historical answer/result data if a later source revision is stale.
- Answer keys, grading rubric keys, and private media identifiers are excluded from pre-submit quiz/mission DTOs and realtime events.
- The initial 500-scenario and 1,000-candidate targets are corpus goals, not test fixtures or permission to invent records. Report real ingested, generated, validated, rejected, active, and modality counts separately.
- Exact and normalized-text dedup plus source/claim fingerprint dedup are always active. Semantic dedup is reported as unavailable unless an embedding route is actually configured and exercised.

## Full verification matrix

Run contract/unit tests for every modality and question type; malformed-input and unsafe-URL boundaries; canonical Trust handoff; media authorization; structured-generation schema and Gemini failure handling; grounding/ambiguity/distractor rejection; duplicate and version behavior; source freshness/revision; pre-submit privacy; exact-version attempt binding; mission idempotency/progression/scope denial; migration fresh install and upgrade against a restored production backup; RLS/grants/FKs/indexes/triggers; and full discovered candidate regression with Tavily disabled. Live provider/database checks must identify their environment and candidate SHA, and unavailable external credentials are reported as blocked rather than counted as pass.
